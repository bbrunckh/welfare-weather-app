## 0. How to read this report

**Method.** This is a static review. Every file in `R/` was read in full or searched for specific patterns. The full path data → Step 1 → Step 2 → Step 3 was read line by line. R is not installed in the review container, so **no tests, benchmarks or profiles were run**. Every performance impact below is an estimate from reading the code. Measure each one with the existing harnesses (`dev/bench_*.R`, `dev/run_step2_benchmark.sh`) before and after any change.

**Optimisation guidelines.** The repository has no file called `optimization_guidelines`, so I used `review/profiling_optimization.md` as the guideline. I applied its engineering principles, phases 0–8, the 2x benefit gate, "characterise before changing", the bit-identical-or-pre-approved-tolerance rule, and the memory-envelope rule. I used `review/performance-audit.md` and `review/step2-optimization-decision-record.md` as the record of what is already done or rejected. The recommendations do **not** reopen any rejected experiment unless a new reason is given. The rejected experiments are: survey join cache, row-batched RIF, reference weather as default, shared SSP monthly cache, broad collapse/kit substitution, and the initial mirai prototype.

**IDs.** New findings use a `CR-` prefix (e.g. `CR-SEC-01`) so they don't collide with the existing `SEC-`, `PERF-`, `S2-P`, `S3-P`, `INT-`, `REACT-` and `UI-` IDs. Where a finding overlaps an existing ID, the existing ID is cross-referenced.

**Severity:** Critical · High · Medium · Low · Info. **Effort:** S (< 1 day), M (1–3 days), L (> 3 days).

**Security write-ups** are kept at the level of impact, location and remediation, on purpose. They contain no reproduction steps.

## 1. Executive summary

For a research app of this size, the codebase is in good engineering shape:

- Business logic lives in pure `fct_*` files, and many behaviours have characterisation tests.
- SQL literals are escaped.
- Run signatures and stale-result banners guard against mismatched results.
- RNG is seeded deterministically.
- Step 2 payloads are compact, caches are bounded, and DuckDB filters and projections are pushed down.
- Maps use a columnar MapLibre engine.
- Credentials are redacted from exported configs and provenance.

The remaining risk is concentrated in a few places:

1. **Trust boundary in the data-connection layer (critical).** Connection parameters from the browser are trusted, even on the auto-connect production deployment where the form is hidden. Server credentials can be combined with locations the operator never configured.
2. **Two correctness bugs that bias headline results:**
   - The CMIP6 baseline climatology is a mean of two means.
   - RIF simulations mix currencies when LCU is selected.
3. **The largest backend wins left are structural, not micro-optimisations:**
   - Step 3 hashes whole surveys and model fits on every decomposition call. Stop doing that.
   - Step 2 re-queries identical weather on every re-run. Stop doing that.
   - Split each per-key prediction into a static per-household part, computed once, and a weather part. Most of the RIF India runtime is in the per-key pipeline (202 of 257 s, per the decision record).
   - Make long runs non-blocking with `ExtendedTask` + `mirai` over the existing `step2_compute()` boundary.

## 2. Security

Each item gives the risk, the affected code and the remediation. None of these should block research use on a trusted single-user desktop. All of them should be fixed before, or as a condition of, multi-user deployment on Posit Connect.

### CR-SEC-01: Client-supplied connection parameters are trusted (Critical, effort M)

**Risk.**

- The Step 0 connection layer builds connection parameters from Shiny inputs. On deployments where `.auto_connect()` hides the form and connects from environment variables, those inputs and the apply handler are **still registered** on the server (`mod_0_overview.R:87-132` hides the UI, while `:296-324` and `:438-533` are unconditional).
- `build_connection_params()` falls back to environment variables field by field (`%|||%`, `fct_connection.R:46-52`). A connection can therefore end up with a host value that did not come from server configuration combined with server-held service-principal credentials.
- The token request is then sent to that host (`fct_overview_metadata.R:264`, `fct_load_data.R:302-307`).

The result is a path for long-lived service credentials to leave the server. It exists on exactly the deployment mode intended for production.

**Remediation.**

1. In auto-connect or production mode, take connection parameters **only** from server configuration. Don't read connection inputs, and don't register the apply observer. Gate this on the server, not just in the UI.
2. Never mix sources within a single connection. Either every field comes from the UI (and then no server secret is used) or every field comes from the environment.
3. Validate the Databricks host against an allowlist from config (e.g. the configured workspace URL, or `*.azuredatabricks.net` / `*.cloud.databricks.com`). Require `https://` and reject other schemes, user-info and non-default ports.
4. Rotate the service-principal secret after the fix ships if any public or shared deployment has run this code.
5. Add a regression test: with auto-connect enabled, setting connection inputs from a test session has no effect on `connection_params()`.

### CR-SEC-02: Confused deputy on storage locations (High, effort M)

**Risk.** In manual-connection mode, the user chooses the S3 bucket, Databricks volume path, or local path, but the read uses the **server's** credentials (environment keys or the service principal) or the server's filesystem permissions (`fct_load_data.R:535-677`). Any app user can read whatever the server identity can reach, not just the WISE data.

**Remediation.**

- Keep an allowlist of permitted buckets, volume roots and local roots in `golem-config.yml`, and check it on the server.
- Disable the `local` source in production config.
- When a location is user-chosen, require user-supplied credentials and never fall back to server environment credentials.
- Canonicalise local paths (`normalizePath(mustWork = TRUE)`) and confirm they are under an allowed root.

### CR-SEC-03: DuckDB secrets are process-wide and unscoped (High, effort M)

**Risk.**

- The Databricks bearer token is registered as a DuckDB `http` secret **without `SCOPE`** (`fct_load_data.R:334-345`). DuckDB therefore attaches it to any HTTP(S) request the connection makes.
- S3, GCS and Azure secrets are created on the process-wide connection held in `.duck` (`fct_load_data.R:535-677`).
- Lazy `_ld_` views (`:703-714`) are evaluated at collect time with whatever secret is current at that moment, and they are never dropped.
- On Posit Connect, several sessions share one R process. One session's credentials or location can therefore affect another session's queries.

**Remediation.**

- Add `SCOPE '<https://host/...>'` or `SCOPE 's3://bucket/prefix'` to every `CREATE SECRET`.
- Give secrets per-session names and drop them, along with the session's views, in `session$onSessionEnded()`.
- Collect eagerly where results are small (metadata, variable lists). For large lazy relations, use one DuckDB connection per session, or per worker once Phase 3 lands, instead of one per process. This is also a prerequisite for `ExtendedTask` workers (guideline Phase 3, "Cache and connection safety").

### CR-SEC-04: Weather disk cache key and contents (High, effort S–M)

**Risk.**

- The cache key (`fct_get_weather.R:266`) is a digest of version, *relative* file names, columns, time column and dates. It does not include the source: backend, host, bucket or volume, and prefix.
  - Two sources with the same relative layout share entries.
  - A cache hit (`:272-278`) returns data without touching the remote, so the user's access to the source is never checked.
- The cache lives in a shared `tools::R_user_dir()` directory.
- It persists survey→H3 location mappings (`:902-913`). These come from `microdata/` and should be treated as part of the microdata.
- Robustness issues in the same code:
  - The temporary path `paste0(path, ".tmp")` (`:288`) is not unique per process, so concurrent misses can corrupt an entry.
  - Eviction is described as LRU by mtime but hits never update mtime, so it is actually FIFO (`:211-230`).
  - A file referenced by a live lazy view can be evicted underneath it.

**Remediation.**

- Add a **source identity** to the key: backend, host/bucket/volume, prefix, plus a non-secret credential-scope id.
- Don't cache location mappings on disk; keep them in memory for the run.
- Put the cache in a private directory (mode `0700`), per deployment.
- Write with `tempfile(tmpdir = dir)` and then `file.rename()`.
- Call `Sys.setFileTime()` on a hit to get real LRU.
- Never evict files opened in the current process (keep a pin set).
- If the access check matters, do a cheap remote existence check (HEAD/list) before serving a hit.

### CR-SEC-05: Config import can change connection fields, and exports reveal infrastructure (Medium, effort S)

**Risk.**

- Imported configs can set `db_workspace`, `local_path` and bucket fields (`fct_export.R:280-307`). This hands the CR-SEC-01/02 surface to a file the user uploads.
- Exports and provenance (`fct_provenance.R:33-51`) redact credentials but still include the workspace URL, volume path, bucket and local path.

**Remediation.**

- Ignore connection fields on import in production mode, and show a notice.
- Make infrastructure identifiers opt-in in exports, or replace them with a deployment label.

### CR-SEC-06: Outbound HTTP calls have no timeouts or retry policy (Medium, effort S)

**Risk.** The token and file requests (`fct_load_data.R:302-307,409-414`) have no `req_timeout()`. A slow endpoint can hold the shared R process indefinitely, which turns a remote outage into an app outage (see CR-SEC-07).

**Remediation.**

- Add `httr2::req_timeout()` (e.g. 30 s for the token, longer for files).
- Add `req_retry(max_tries = 3, is_transient = ...)` with backoff.
- Add `req_error(body = ...)` so error bodies are summarised, not echoed.

### CR-SEC-07: Unbounded synchronous work on a shared process (Medium, effort L; see CR-PERF-04)

**Risk.** Model fitting, LASSO, Step 2 and Step 3 run synchronously with no size limits. On Posit Connect, one large request blocks every session on that process, which is an availability problem.

**Remediation.**

- Move this work to `ExtendedTask` workers (CR-PERF-04).
- Configure Connect's *max connections per process* and *max processes*.
- Add server-side limits from config: maximum households, keys and years per run.

### CR-SEC-08: Raw error messages shown to users (Low–Medium, effort S)

**Risk.** `conditionMessage(e)` is shown verbatim in notifications and UI (`mod_0_overview.R:505`, `fct_load_data.R:708`, `mod_2_01_weathersim.R:826-838`). These messages can contain internal paths, URLs and SQL.

**Remediation.**

- Log the full condition server-side with a run or error id.
- Show the user a short, classified message plus that id.
- Add a central `wise_user_error()` helper.

### CR-SEC-09: Lower-risk items (Low / Info)

- `dev/03_deploy.R` puts `"data/"` in `appFiles`, so a developer with local microdata in `data/` would upload it with the bundle. Remove it, or add an explicit guard. The ignore-everything `.gitignore` already protects git; the deploy path needs the same protection.
- The bundled DuckDB extension binaries in `inst/duckdb_extensions` are tied to the DuckDB version. Pin and verify their checksums in the same way as the vendored map assets (`fct_hexmap.R`), and fail clearly on a mismatch.
- Inline `onclick`/`setTimeout` scripts (e.g. `mod_1_06_model.R:304-307`) prevent a strict Content-Security-Policy. Move them to `custom.js`.
- Links with `target="_blank"` have no `rel="noopener noreferrer"` (`mod_0_overview.R:31-35,76-80`). Modern browsers imply `noopener`, so this is Info only.

## 3. Bugs and correctness

### CR-BUG-01: CMIP6 baseline is a mean of means (High, effort S)

**Where:** `fct_get_weather.R:1228` (`h3_hist_raw`, historical file) and `:1271-1282` (`union_all(h3_hist_raw, h3_ssp_raw) |> group_by(model, h3, month) |> summarise(mean)`).

**What.** Both inputs are already monthly climatologies, so the result gives each file equal weight whatever the number of years it covers. With a 1991–2020 baseline, the 6 SSP years (2015–2020) get about 50% of the weight instead of 6/30. They are also the warmest years, so the baseline is biased warm and future deltas are understated. If the SSP file overlaps years already in the historical file, those years are counted twice.

**Fix.**

- Union the *raw monthly rows* before aggregating, clipping the historical file to `< 2015` and the SSP file to `>= 2015`.
- Alternatively, carry `sum` and `n` from each part and compute `sum/n`.
- Add a characterisation test with a fixture where the two parts have different lengths.

This changes numbers, so record it in a decision log.

### CR-BUG-02: RIF + LCU currency mismatch (High, effort M)

**Where:**

- `prepare_outcome_df` multiplies welfare by `ppp2021` for LCU before taking `log` (`fct_results.R:40-46`).
- `predict_rif` uses `y_raw <- svy[[outcome]]` with only `log` applied (`fct_rif_sim.R:324-338`).
- The decomposition does the same (`fct_policy_decompose.R:136-146,555-556`).

**What.** `ecdf(train_data[[outcome]])` is built on log-LCU but evaluated at log-PPP. Every household's τ is clamped to the lowest quantile, and point predictions combine a PPP level with an LCU-model delta. Steps 2 and 3 have no LCU handling at all.

**Fix.** Convert once, through one function used by training, simulation and decomposition, for example an `outcome_to_model_scale(y, svy, so)` function.

- Store the scale (units, transform, ppp column) on `model_fit`.
- Assert in `predict_rif` that the baseline is on the training scale (e.g. that the medians of the two are within a tolerance).
- Add a test with `units = "LCU"`.

### CR-BUG-03: RIF transform computed before complete-case filtering (Medium, effort S)

**Where:** `backend$prepare_outcome` (RIF `compute_rif_multi`, `fct_fit_model.R:243-257`) runs at `:846`. Complete-case filtering happens at `:986`.

**What.** q_τ and the KDE density f(q_τ) are estimated on rows that are later dropped. As a result the RIF does not satisfy E[RIF] = q_τ on the estimation sample.

**Fix.** Compute the RIF after the complete-case filter, or recompute it on the filtered rows. Check E[RIF] ≈ q_τ in a test.

### CR-BUG-04: Weighting is inconsistent across the pipeline (Medium, method decision)

**What.**

- Unweighted:
  - `feols`/`feglm` (no `weights =`).
  - RIF quantiles and the density estimate.
  - SP `exante_poor` targeting, which uses an unweighted `quantile()` (`fct_policy_sim.R:599`).
- Weighted: all summaries, and the SP budget.

The targeting threshold is therefore a sample quantile, not a population quantile, while costs are population-weighted.

**Fix.** Ask the method owners to decide this explicitly. At minimum, weight the targeting quantile with `collapse::fquantile(w = weight)`, and document whether the regressions are meant to be unweighted (a defensible choice for causal estimation, but it should be stated in the model card).

### CR-BUG-05: Rolling windows assume gap-free monthly series (Medium, effort M)

**Where:** `ROWS BETWEEN n PRECEDING` (`fct_get_weather.R:992,1140`); `if_all(!is.na)` drop (`:895`).

**What.** A missing location-month shifts the lag window silently. Dropping a cell-month when any variable is NA removes it for all variables.

**Fix.** Either densify the calendar (left join to a complete month grid per location) or use `RANGE BETWEEN INTERVAL n MONTH PRECEDING AND CURRENT ROW` on a date column. Apply NA filtering per variable.

### CR-BUG-06: Partial-coverage CMIP6 members are kept (Medium, effort S)

**Where:** `fct_get_weather.R:1305-1319,1404-1409`.

**What.** `n_complete > 0` keeps any member with *some* coverage. Inner joins then drop location-months, so those members have fewer rows than the historical key. This contradicts the "complete set" comment and makes ensemble members non-comparable.

**Fix.** Require full coverage, or report the reduced coverage in the failure ledger and exclude the member from ensemble statistics.

### CR-BUG-07: Prediction/loading row alignment is not asserted (Medium, effort S)

**Where:** `fct_aggregation_delta.R:512` (`F_full[idx, ]`); `fct_simulations.R:737-743` (`model.matrix(type = "rhs")`); comment at `fct_predict_outcomes.R:160-165`.

**What.** `model.matrix()` can drop NA rows while `predict()` returns NA rows. Nothing checks `nrow(F_loading) == length(y_point)`. The "rowids" comment describes behaviour fixest does not have.

**Fix.** Assert alignment at the `step2_compute()` boundary, as the guideline's "validate at boundaries" principle requires. Build `F_loading` with `na.action = na.pass`. Correct the comment.

### CR-BUG-08: Policy lever gating uses regex substring matching (Medium, effort S)

**Where:** `Filter(function(v) any(grepl(v, model_vars, ignore.case = TRUE)), cols)` (`fct_policy_sim.R:694`), and the same pattern in the lever modules' `show_*` logic.

**What.** `piped` matches `piped_to_prem`. Column names containing regex metacharacters behave unpredictably.

**Fix.** Match parsed model terms exactly: take the variable names from `all.vars(formula)` or from the fixest `fml` components, and use `%in%`.

### CR-BUG-09: Blank Azure key shadows the environment key (Low, effort S)

**Where:** `fct_connection.R:40`. It uses `%||%`, whereas the neighbouring fields use `%|||%`.

**What.** An empty UI key overrides `AZURE_STORAGE_KEY`, which contradicts the documented behaviour. Azure and HuggingFace are also not offered in the Step 0 UI (`mod_0_overview.R:106`), although CLAUDE.md lists them.

**Fix.** Apply CR-SEC-01's "no field-level mixing" rule, then align the docs.

### CR-BUG-10: Three different Gini implementations (Medium, effort S)

**Where:** `fct_aggregation.R:107-111` (weighted midpoint), `:112-117` (unweighted, no `−1/n` correction), `:480-498` (trapezoid). Weighted median NA weights at `:53-63`.

**What.** The same statistic differs by O(1/n) depending on the code path. The weighted median includes weights of NA welfare in its denominator.

**Fix.** Use one `wise_gini(x, w)` everywhere, with tests against a reference value (e.g. `ineq::Gini` / `acid::weighted.gini` on a fixture). Drop NA pairs before computing weighted quantiles.

### CR-BUG-11: Orphan inputs and dead outputs in Step 2 Results (Medium, effort S)

**Where:** `mod_2_02_results.R`. No UI element is created for `show_coef_uncertainty`, `uncertainty_band`, `cmp_group_order` or `bandwidth_p0`. `updateCheckboxInput(session, "show_coef_uncertainty", ...)` at `:944` targets an input that doesn't exist.

**What.**

- `show_coef` is always `FALSE`, in Step 2 (`:1474,1492`) and in Step 3 (`mod_3_07_results.R:133`, which feeds `skip_coef` in `mod_3_09`).
- Coefficient draws can therefore be computed but are never shown. That is both a correctness gap and wasted work.
- `summary_box_plot`, `incidence_plot`, `incidence_table` and `coef_uncertainty_status_ui` are rendered but never placed in the UI.

**Fix.** Either restore the controls or remove the dead branches, and skip coefficient draws whenever they cannot be displayed.

### CR-BUG-12: Non-namespaced element id (Low, effort S)

**Where:** `mod_2_02_results.R:1812,1827,1842` (`#results_section`).

**What.** The id and its global selector break if the module is instantiated twice, and they differ from the namespaced Step 3 equivalent.

**Fix.** Use `ns("results_section")`.

### CR-BUG-13: GCM names replaced by `model_n` (Low, effort S)

**Where:** `fct_run_simulation.R:414-416`.

**What.** Climate-model identity is lost in labels and exports. That hurts provenance and comparison with external CMIP6 results.

**Fix.** Keep the source name in a `gcm` column and use `model_n` only as the display key.

### CR-BUG-14: Step 3 reads live reactives instead of the run snapshot (Medium, effort S)

**Where:** `mod_3_06_policy_sim.R:609-618` (`policy_scenarios`).

**What.** Editing a lever after a run changes what the results panels describe. This breaks the guideline's "inputs snapshotted at invocation" rule.

**Fix.** Read from the run snapshot, and show the stale banner when the live inputs differ.

### CR-BUG-15: S3 methods defined inside a module closure (Low, effort S)

**Where:** `mod_2_02_results.R:632-646` (`[[.wise_lazy...` etc.).

**What.** Dispatch works only from that environment, so any code path outside it silently uses the default method.

**Fix.** Move the methods to a `fct_` file and register them with `S3method()` in `NAMESPACE`.

### CR-BUG-16: Silent row loss and duplication in joins (Medium, effort S)

**Where:**

- `merge_survey_weather` (`fct_weatherstats.R:58-65`): an inner join, plus a pointless `group_by()`/`ungroup()`.
- `convert_lcu_to_ppp` (`fct_surveystats.R:117`): a left join with no `relationship =` guard.

**What.** Households without weather are dropped without any count being reported. Duplicate CPI rows would duplicate households, and a missing CPI gives NA welfare silently.

**Fix.**

- Use `relationship = "many-to-one"` and `unmatched = "error"` where appropriate.
- Report the number of dropped rows in the UI.
- Remove the no-op grouping.

### 4.3 Details

#### CR-PERF-01: Step 3 signature hashing on every call (High)

**Where:**

- `.validate_decomposition_context` → `.decomposition_context_signature`, which hashes `.sig_plain(model_fit)`, `.sig_plain(svy_baseline)` and `.sig_plain(svy_policy)` (`fct_policy_decompose.R:405-438`).
- It is called from `decompose_policy_effect` (`:805-808`) and `.policy_central_delta` (`:938-940`).
- `.weather_context_key` hashes `.sig_plain(weather_raw)` on every call (`:502-506`).

**Call count.** The hash runs for the historical decomposition, for the adverse bases, for each pipeline inside `apply_policy_delta_to_baseline` (about 17 per scenario), and per scenario × simulation year (`mod_3_06_policy_sim.R:419-476`; e.g. 3 SSPs × 3 periods × 30 years = 270). Each call serialises the whole fit, which includes `train_data` and `.snap$survey_weather` (see CR-PERF-07), plus two full survey frames.

**Change.**

1. At run start, build the context once and stamp it with `run_identity`. The `context`/`run_identity` arguments already exist.
2. Validate with `identical(ctx$run_identity, run_identity)` and a cheap structural check (dimensions, column names, key hash of row ids) instead of hashing the full content.
3. If content hashing is still wanted, hash only once at context creation, using `rlang::hash()` (xxhash128, much faster than serialize + md5).
4. Don't split all scenario weather by year upfront (`mod_3_06_policy_sim.R:347-355`). Index lazily with `split(seq_len(n), year)` computed once.
5. Consider vectorising the per-year decompositions. The model, the survey and the policy delta are the same across years, and only the weather slice changes, so one grouped computation over (year, household) can replace T calls.

**Verification.** Characterisation test on a fixture: the decomposition output must be bit-identical before and after; count calls to the hashing function with `testthat::local_mocked_bindings`.

#### CR-PERF-02: Weather reuse across re-runs (High)

**Where:** `mod_2_01_weathersim.R:728-768` → `fct_run_simulation.R:424-446` re-runs `get_weather()` for every key on every click. The Step 1 weather load (`mod_1_05_weatherstats.R:164-167`) already covers the historical comparison dates.

**Change.**

- Add a run-scoped, session-scoped weather result cache keyed by a **weather signature**: source identity, weather variables and transforms, lags, H3 resolution, scenario/SSP/period, baseline window, survey wave dates. Leave out residual, uncertainty and display settings.
- Size-bound it with `cachem::cache_mem(max_size = ...)`, or store a reference into the existing weather store (`fct_step2_payload.R:206-219`).
- Reuse Step 1's historical weather for Step 2's historical key when the signatures match.

**Why this is not the rejected "shared SSP monthly cache".** That experiment held SSP *monthly intermediates* across SSPs and periods inside one run. This proposal caches the *final per-key weather* of the previous run, so memory is bounded at one run's worth, which the app already holds. Measure RSS against the India envelope before enabling it by default.

#### CR-PERF-03: Factorised per-key predictor (High; supersedes PERF-15)

**Where:** for each key, `predict.fixest(newdata = N_hh × years)` (`fct_predict_outcomes.R:149-165`) and then `model.matrix(type = "rhs")` again to build `F_loading` (`fct_simulations.R:572-755`, `:737-743`). For RIF, `pred_base` is identical across keys but is recomputed (`fct_rif_sim.R:106-146,408-417`).

**Idea.** For a linear index, `ŷ_it = s_i + W(loc_i, t)·g_i`, where:

- `s_i` is the household-static part: fixed effects, controls and non-weather terms. Compute it **once** per run.
- `g_i` is the household-specific weather slope vector: the main weather coefficients plus interaction coefficients × moderator values. Compute it **once** per run.
- `W` holds the weather design columns for the key: transforms, polynomials and bins of the key's weather. This is the only per-key part.

Per key the work becomes one `rowSums(W * G)`, or a small matrix multiply, over N × T rows with only the P_w weather columns. The coefficient-uncertainty loading `F_active` only needs the weather columns plus the static columns' fixed contribution. The "active mask" design already isolates these (`test-active-mask.R`).

- For logit `feglm`, factorise the linear predictor the same way and apply the link afterwards.
- For RIF, the per-key delta is `(W_scen − W_base)·β_w,τ`. Fixed effects and covariates cancel, so only the weather columns are needed, and `pred_base` is hoisted out of the loop.

**Guardrails.**

- This is a numerical change in evaluation order, so agree the field-level tolerance first (guideline: "Correctness").
- Keep the `predict.fixest()` path as the reference and the fallback for unsupported formula shapes, as direct RIF prediction already does.
- Unseen FE levels must still fall back.

#### CR-PERF-04: Non-blocking runs (High; guideline Phase 3)

**Where:** `withProgress()` in `mod_1_06_model.R`, `mod_1_07_results.R`, `mod_2_01_weathersim.R:728` and `mod_3_06_policy_sim.R:285`. `step2_compute()` (`fct_step2_compute.R`) is the pure entry point Phase 2 asked for, but only the tests call it.

**Change.**

1. Route the Shiny Step 2 button and the batch scripts through `step2_compute()`. This finishes Phase 2 and keeps the serial reference.
2. Wrap it in `shiny::ExtendedTask$new(function(snapshot) mirai::mirai(wiseapp::step2_compute(snapshot), snapshot = snapshot))`, with a `bslib::input_task_button()`.
   - Start `mirai::daemons(n)` at app start, with n from config, and load the package on each daemon with `mirai::everywhere()`.
   - Each worker opens its own DuckDB connection and sets its own RNG kind and seed. Both are already inside `step2_compute()`.
3. On completion, compare the result signature with the current one before committing. Keep `.busy_guard()`.
4. Repeat for Step 1 (fit + LASSO). Do Step 3 only if profiling shows it needs it.

**Why this does not reopen the rejected mirai prototype.** That prototype failed because worker serialisation captured closures. `step2_compute()` is now a top-level, closure-free function with an explicit snapshot. Phase 3 is also **non-blocking serial** execution, not key-level parallelism. The 2x gate applies to parallelism (Phase 5), not to keeping other sessions responsive.

**Prerequisites:** CR-SEC-03 (per-connection secrets), CR-SEC-04 (atomic cache writes), CR-PERF-13 (per-worker DuckDB memory and threads).

#### CR-PERF-05: Pre-aggregate weather offline (High, out of app scope)

The app currently scans gridded parquet files and aggregates them to H3/location × month at request time. The data-prep pipeline could publish two things per country:

- location-month weather for the survey locations (ERA5 and CMIP6 per member);
- per-member monthly baseline climatologies, which would also fix CR-BUG-01 by construction.

This turns Step 2's weather stage into a small keyed read. It is the largest possible weather win, but it changes the data contract, so treat it as a data-engineering project with its own equivalence test against the current SQL.

#### CR-PERF-06: Aggregation and Results overheads (Medium)

- `.aggregation_preparation_key` hashes the full `y_point`, `sim_year`, `weight`, `id_vec` and train residuals with md5 over `serialize()` on every call, including cache hits (`fct_aggregation_delta.R:357-377`). Use the pipeline's identity token, assigned once when the pipeline is created.
- `which(sim_year == year)` runs once per year, which is O(N·T) (`fct_aggregation_delta.R:392`). Use `split(seq_along(sim_year), sim_year)` once.
- Nested `vapply` in `aggregate_pipeline_table` is O(T² · models) (`fct_aggregation.R:813-817`).
- In `mod_2_02_results.R`:
  - `.by_model_matrix` hashes its input table on every call (`:1046`).
  - `derived_results_frame` hashes each entry (`:897`).
  - The point-range, two timeseries, exceedance and threshold views each re-run `.apply_contrast_sd` on the same tables.

  Compute the derived frame once per (run, display settings) and have every view read from it.
- Step 3 re-aggregates the Step 2 baseline through a separate cache (`fct_policy_sim_compare.R:1360-1520`). Reuse the Step 2 aggregation, keyed by run identity.

#### CR-PERF-07: Model-fit memory (Medium; overlaps P4)

`model_fit` keeps three copies of the data (`fct_fit_model.R:1072-1129`, `mod_1_07_results.R:173-179`):

- `train_data`: the complete-case frame with **all** columns;
- `.snap$survey_weather`: the full frame again;
- `wise_mm`: an N × P design frame for fit 3.

Keep only:

- the columns the formulas use, plus row ids;
- the ecdf/quantile metadata RIF needs;
- a reference to the snapshot, not a copy.

`filter_valid_vars` builds an N × C double matrix over **all** columns (`fct_model_select.R:242-244`). Use `collapse::fnobs()` / `fvar()` on the candidate variables only.

#### CR-PERF-08: Step 1 diagnostics rendering (Medium)

- `plot_residual_panels` fits `geom_smooth(method = "loess")` over the full N (`fct_results.R:616-633`). Loess is O(N²) in memory without `surface = "interpolate"` tuning.
- `renderPlot` re-executes on every container resize, so the smoother is refitted each time (`mod_1_08_modelfit.R:208-214`).
- `plot_resid_weather` draws every point (`fct_results.R:2165-2182`), and `geom_rug` is drawn over all N (around line 1630).

**Change.**

- Precompute binned means (e.g. 50 quantile bins with `collapse::fmean(g = )`) or a `mgcv::bam` smooth once, in a reactive.
- Draw points from a fixed-seed subsample (e.g. 20k) and say so in the caption.
- Wrap the plots in `bindCache(model_signature, ...)`; `renderPlot` caching handles sizes through `sizePolicy`.
- `.fixest_vcov_spec` calls `summary()` just to test the VCV (`fct_results.R:124`), which recomputes clustered standard errors. Inspect `fit$call`/`fit$summary_flags` instead.

There is no `bindCache()` anywhere in the app. Plots that are a pure function of a run should use it.

#### CR-PERF-09: Step 1 data loading (Medium)

- **Survey load.**
  - `load_data(collect = TRUE)` collects **all** columns, then `collect_deterministic` sorts by **all** columns in R with `dplyr::arrange(.locale = "C")` (`fct_load_data.R:93-106`, called from `mod_1_02_surveystats.R:218`).
  - Project the columns from `variable_list` in the DuckDB query.
  - Put `ORDER BY <unique keys>` in SQL. If R-side ordering is still needed, use `data.table::setorderv()` on the key columns only. Sorting by keys is deterministic only if the keys are unique, so assert that.
- **H3 table.** `h3_local |> compute()` materialises every column of the H3 parquet (`mod_1_02_surveystats.R:264`). Select the 6 needed columns first.
- **Dead geometry.** `st_asgeojson(st_geomfromtext(h3_cell_to_boundary_wkt(...)))` and `st_extent` are computed for every cell (`mod_1_02_surveystats.R:287-300`), but since the move to MapLibre `geom` is only used for `!is.na(geom)` / `nchar(geom) > 2` filters (`fct_outcome.R:545,686`, `fct_weatherstats.R:1412`, `mod_1_02_surveystats.R:116-117`).
  - Replace those filters with `h3_is_valid_cell()`.
  - Compute bounds from `h3_cell_to_lat/lng`, or on the client with h3-js.
  - This also removes the need to load the `spatial` extension.
- **File listing.** `list_available_files` runs `list.files(recursive = TRUE)` over the whole data tree (`fct_sample.R:31`, called from `mod_1_01_sample.R:38`). List only `microdata/<unit>/`, and cache the result per connection with a short TTL.

#### CR-PERF-10: Small, free wins in Step 2 (Low–Medium)

- Remove the forced `gc()` calls in `get_weather` (`fct_get_weather.R:1503,1528`) and `fct_run_simulation.R:468,548`. A full GC per period or member costs time and rarely lowers peak RSS. If one is needed for the memory envelope, run it once per run.
- `.results_defensive_copy` does a serialise/unserialise round trip (`fct_step2_payload.R:351-362`). R's copy-on-modify already protects the data; drop it, or copy only mutable environments.
- `.wx_process_tree_rss_bytes()` starts a `ps` subprocess on every `get_weather` call (`fct_get_weather.R:773`). Call it only when bounded collection is active, or use `ps::ps_memory_info()`.
- `split(batch, batch$model)` on a tibble (`fct_get_weather.R:1444`). Use `vctrs::vec_split()` or `collapse::rsplit()`.
- The weather store uses `saveRDS()` with gzip (`fct_step2_payload.R:206-219`). Use `compress = FALSE` for temporary run files, or `qs2::qs_save(nthreads = )`.
- `get_weather` sets the **global** DuckDB `threads` on the shared connection (`fct_get_weather.R:783`), which affects concurrent sessions. Fold this into per-worker connections (CR-PERF-04).

#### CR-PERF-11: Modelling (Medium; guideline Phase 6 for LASSO)

- Fits 2 and 3 share the same fixed effects. A single fixest stepwise call (`csw0()` over the control block, with the FE after `|`) reuses the demeaning across both models. Check the formula expansion against the fixest stepwise docs.
- Set `fixest::setFixest_nthreads()` explicitly from config. The default (half the host cores) is wrong on Connect.
- LASSO builds a dense `model.matrix` that includes the FE dummies (`fct_fit_model.R:485`). Partial out the FE with `fixest::demean()` (Frisch–Waugh–Lovell), then run `glmnet` on the demeaned weather/controls. This is much smaller and faster, and it gives the same penalised solution if the FE are left unpenalised (already the intent).
- The repeated `cv.glmnet` runs vary only the folds. Pass `foldid` explicitly and reuse the design across repeats.
- Re-check `nrow(df) > 50000L` and `parallel_min_n = 20000L` after the change (Phase 6).

#### CR-PERF-12: Dependencies and startup (Low–Medium)

- `xgboost`, `ranger` and `parsnip`/`hardhat` are unreachable from the UI: `model_type_choices` offers linear, logistic and RIF only. Their engine entries and the `predict_outcome` parsnip/broom branches are dead code.
- `Hmisc` is used once (`fct_outcome.R:98`). Use `collapse::fquantile(w = )`.
- `mice` and `glmnet` are imported in `NAMESPACE`, so they (and `lme4` and others) load at startup. Move them to `Suggests`, or use `pkg::fun` with `requireNamespace()` in the code paths that need them.
- Possibly unused functions to confirm and remove: `resimulate_with_svy`, `compute_exceedance_ribbon`, `aggregate_sim_preds`, `apply_log_backtransform`, `residual_method_ui`, `.fixest_vcov`, `.fixest_coeftable`. `aggregate_outcome` and `compute_rif` are used by `batch/` and `dev/`.
- `manifest.json` lists 160 packages. Trimming these reduces bundle restore time on every Connect deploy.

Follow the guideline: remove dependencies in a separate PR, with characterisation tests.

#### CR-PERF-13: DuckDB configuration (Low–Medium)

- Set `memory_limit` (e.g. a fraction of the Connect process limit) and `temp_directory` so large joins spill to disk instead of being killed for running out of memory.
- Set `threads` per connection or worker.
- `DROP VIEW` the `_ld_` views and temporary tables when a session ends.
- Use `preserve_insertion_order = false` where order is restored with `ORDER BY` anyway.

#### CR-PERF-14: Client-side work (Low)

- `custom.js:25`: a `MutationObserver` runs `scan()` on **every** DOM mutation. Debounce it with `requestAnimationFrame`, or limit it to added nodes that match the selector.
- `hexmap.js:469` adds a second observer. Merge the two.

#### CR-PERF-15: Cold start (Low)

`app.R` runs `pkgload::load_all()`, which parses and sources about 46k lines on every process start and needs `pkgload` and its dependencies in the bundle. Deploying the installed package lazy-loads byte-compiled code. Examples are `library(wiseapp); run_app()` from a built tarball in the manifest, or Connect's package-based deploy. This matters more once max-connections-per-process is lowered (§9), because that means more process starts.

## 6. Modern R packages and practices

Recommendations are scoped by the guideline's rule that "overlapping-purpose packages are not necessarily interchangeable": each change is targeted and measured, not a broad substitution.

| Need | Current | Recommended | Notes |
|---|---|---|---|
| Non-blocking long runs | `withProgress()`; no async | `shiny::ExtendedTask` + `mirai` (+ `bslib::input_task_button`) | shiny 1.13, bslib 0.10 and promises 1.5 are already locked; add `mirai`. Use `mirai::everywhere()` to load `wiseapp` on daemons. |
| Core counts | `parallel::detectCores()` | `parallelly::availableCores(omit = 1)` | Container- and Connect-aware; never NA. |
| Hashing and identity | `digest` md5/xxhash over `serialize()` per call | Identity tokens assigned when objects are created; `rlang::hash()` (xxhash128) when content hashing is unavoidable | Faster, and avoids hashing environments by accident. |
| Caching | Many bespoke environment caches | `cachem::cache_mem(max_size=)` / `cache_disk()`; `bindCache()` for outputs; `memoise` for pure helpers | Gives consistent eviction and size limits. |
| Weighted quantiles | `Hmisc::wtd.quantile` | `collapse::fquantile(w = )` / `fnth()` | Drops a heavy dependency. |
| Splitting and sorting | `split()` on tibbles; `dplyr::arrange` on all columns | `vctrs::vec_split()`, `collapse::rsplit()`; `data.table::setorderv()` on keys, or SQL `ORDER BY` | Targeted only (broad substitution was rejected). |
| Stepwise FE models | Separate fits | `fixest` `csw()`/`sw()`; `setFixest_nthreads()`; `fixest::demean()` for LASSO | Same estimates, less demeaning. |
| HTTP | `httr2` with no timeout or retry | `req_timeout()`, `req_retry()`, `req_error()`; `req_perform_parallel()` where it fits | Availability and clearer errors. |
| Query engine | DuckDB 1.5 + dbplyr | Keep. Add scoped secrets, `memory_limit`, `temp_directory`, per-worker connections. Consider `duckplyr` only for measured R-side hotspots. | DuckDB push-down is an option, not a rule (guideline Phase 4). |
| Temporary serialisation | `saveRDS()` gzip | `qs2` (multithreaded) or `saveRDS(compress = FALSE)` for run-local files | Faster weather store. |
| Input validation | Ad hoc `stopifnot` | `checkmate` assertions at public entry points | Fits "Validate at boundaries". |
| Logging | `message()`/`cat()` | `logger` (JSON layout) or `cli` with a run id and the fields from guideline Phase 8 | Never log credentials or household values. |
| Plot rendering | ggplot2, `renderPlot` | `bindCache()` on run-pure plots; `ragg` device (shiny uses it when installed) | Check that `ragg` is in the lockfile. |
| Profiling | `dev/bench_*.R` | `profvis`, `bench::mark` (memory), `reactlog`, `ps` for RSS | Phase 1 harness. |
| Testing | testthat | testthat 3e + `shiny::testServer()` + `shinytest2` end-to-end, with axe-core accessibility checks | §9. |
| Lint and format | none in CI | `lintr` + `styler` (or Posit's `air` formatter) in separate PRs | Guideline Phase 8. |
| CI | none | GitHub Actions `r-lib/actions` v2 (`setup-r`, `setup-renv`, `check-r-package`), `covr` | §9. |
