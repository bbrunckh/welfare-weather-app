**Outstanding — Step 3 with a binary outcome (needs a deeper dive; documented, not changed).** `poor` is declared `type = "logical"` and the *aggregation* layer handles it (`hist_aggregate_choices()` restricts to Mean; `fct_aggregation.R:703` maps it to `"binary"`). The breakage is entirely in the Step 3 decomposition, which is written for continuous log-scale welfare. **Root cause:** a cash transfer's effect on welfare is mechanical — add dollars. Its effect on poverty *status* is not: it is mediated by the poverty line and the welfare distribution, and the model has no coefficient linking transfers to `poor`. The decomposition has no path for that, so it applies the welfare formula anyway. **Mechanism** (`fct_policy_decompose.R:642-646`): `delta_sp <- if (is_log) log(pmax(exp(y_baseline) + sp_transfer, 1e-10)) - y_baseline else sp_transfer` — for `poor`, `is_log` is FALSE, so `delta_sp` is the raw dollar transfer added to a 0/1 indicator; line 744 then converts it as a log change, `pct_main = (exp(delta_main) - 1) * 100`. delta_sp 0.05 (legitimate log-welfare) → 5.13 %; 0.82 (daily, $300/yr) → 127 %; 50 ($50/payment) → 5.18e+23; 300 (annualised) → 1.94e+132. Any chart plotting `pct_*` gets an axis in the 1e23 range, so every other bar collapses to zero height — almost certainly the "graphics break". **Secondary:** the decile chart collapses — line 713 builds deciles via `ecdf(y_baseline)` on a 0/1 vector, only two distinct values survive (7 and 10), so a 10-decile chart shows 2 bars; the simulation arm inherits it — `fct_simulations.R:640-647` adds `sp_vec` to `y_point` on the level scale, dollars onto a predicted probability, so Step 3 Results distributions and exceedance curves are corrupted too, not just the Decomposition tab; the before/after histograms are *not* affected (`fct_policy_sim_compare.R:21` branches on `is_binary`). The same reasoning applies to any non-welfare outcome with an SP transfer configured. Covariate levers (infrastructure, digital, labor, education) are fine — they go through `beta_v * delta_x`, which is in outcome units. **Other open items:** five tests fail on a clean tree and predate this batch (`test-determinism.R` ×3 — Lasso `.Random.seed` restoration; `test-fct-outcome-weather-payloads.R` ×2 — `payload$dash`/`payload$info` NULL). No test asserts a module's return API: an eager-render insert landed *after* nine modules' return `list(...)` and would have replaced their APIs with an `lapply()` result — the suite stayed green; it was caught on inspection and verified through a parent server. Worth a guard test.
